# ak-ui 采用计划

关联：[#15](https://github.com/MilkSU-Official/milksu/issues/15)

## 已经确认的事

- 现网拧巴，是因为 Felinic 原子、自研战术/方舟补丁、安全渲染贴片叠在同一窗口。
- 批准稿比现网更戏服，不能当整页实施源。
- 用户看过隔离预览后同意用 ak-ui 作为下一版成型语言。游戏壳可以留，但每屏只能有一个视觉重心。
- 本目录只是研究预览。生产 `App.vue`、`index.css`、`@felinic/ui` 都还没动。

## 本 PR 做什么、不做什么

做：把可点预览、钉死的 CSS 和截图留在仓库里，方便对照。

不做：不改生产页，不把 `@yunyoujun/ak-ui` 写进 `app/package.json`，不改视觉合同和 `current-objectives.md`，不发版。

## 生产接入顺序

一次只换一条高频路径。控件层仍可以暂时用现有 Vue 组件，先换壳和主操作的视觉，再拆 Felinic。

1. **契约**  
   把战术档案批准稿降成签名来源。产品实施源改成：ak-ui CSS Core +「每屏一个重心」。  
   先定品牌映射：预览里的青/金是原色；进生产前必须决定酸绿是映射到 `--ak-signal-action`，还是暂时跟预览走。
2. **CTF 题库**  
   rail、顶栏、表、选中展开、唯一主按钮「交给 Coding」。验收：打开题库时眼睛先落到当前题和主按钮。
3. **Coding 对话**  
   消息、一条工具行、Composer。不要卷宗、假阶段轨、`FILE NO.`。验收：输入和发送是最重的一块。
4. **设置**  
   分类 + 正在改的那一行。验收：表单不被切角和状态灯抢走。
5. **壳收口**  
   再统一 Profile 和其余浮层。CVE 跟 CTF 同构，不单独开刀。

## 硬边界

- 不用官方 Showcase 的角色图、理智条、3D 透视菜单。
- 不把青/黄稀有度色板拿来区分 CTF / CVE / Coding。
- 不在同一 PR 里删掉整个 `@felinic/ui`。某一页的原子不再被引用后，再从该页拿掉。
- Provider Key、Judge、桌面授权、Pi 工具循环都不因换皮改语义。
- 研究页继续不得进入 `vite` 生产 rollup input。

## 退出

第一条生产路径（CTF 表）如果看完仍然抢不过内容，就停，删研究目录，现网保持 Felinic。不要再叠第四套皮肤。
