## 怎么填写

不必一次填完，也不必为每一行写意见。优先填写你最在意或最想调整的部分：

- **大任务决定：** 可填“保留 / 拆分 / 合并到…… / 后置 / 暂停 / 删除”；
- **优先级：** 可填 `P0 / P1 / P2 / 后期`，也可以直接写自然语言；
- **小任务决定：** 可填“保留 / 修改 / 合并到…… / 后置 / 删除”；
- **新增项：** 在每个大任务后的新增区继续添加，不需要自己分配正式 ID；
- **备注：** 可以写产品直觉、使用场景、验收想法、担忧或“不懂这项有什么用”。

填写规则：

1. 空白表示“暂时没有意见”，不是同意或删除；
2. 修改已有小任务时保留它的 ID，方便和证据台账对照；
3. 你写的内容不会自动触发开发、审批、外部发布或真实平台操作；
4. 我重新读取后会先复述你的改动，并把含糊项转成可验收事项，再请你确认开发批次；
5. 详细实现证据和“还缺什么”不在本文件重复维护，避免两份事实源漂移。

## 一轮填写后的处理方式

用户完成任意一轮填写后，主 Agent 只做以下工作，不直接开发：

1. 读取本文件中所有 `USER-REVIEW` 区域和表格备注；
2. 列出新增、删除、合并、优先级变化和仍有歧义的事项；
3. 对照当前仓库与覆盖台账，指出哪些想法已经实现、哪些需要用户条件、哪些可独立准备；
4. 给出一个或多个有边界的候选批次，每批写明价值、风险、依赖、验收和禁止顺带修改范围；
5. 只有用户明确选定批次后，才恢复该批次的开发。

多轮评估期间，本工作簿是共同讨论区；`current-objectives.md` 仍是范围契约，
`objective-coverage-ledger.md` 仍是证据和百分比事实源。
