# 中文写作规范

> Current。2026-09-25。

适用：PR 正文、`docs/`、README、代码注释、提交信息、issue。用户可见 UI 文案除本篇外还受 `AGENTS.md`「用户可见文案」的约束（双语 `t()`、空控件留白）。

依据：阮一峰《中文技术文档的写作规范》（[ruanyf/document-style-guide](https://github.com/ruanyf/document-style-guide)）、《[中文文案排版指北](https://github.com/sparanoid/chinese-copywriting-guidelines)》、[Microsoft 中文本地化风格指南](https://learn.microsoft.com/zh-cn/style-guide/)。约束的四条规矩写在 `AGENTS.md`「中文写作规范」，本篇只放判例和验证方法。

## 总则

写事实和现场，不写评价和修辞。先讲读者看到什么，再讲代码怎么改。一句只讲一个意思。

## 去除 AI 腔

七条禁止，每条配一个从本仓库真实 PR 里取出的改前改后。

### 1. 禁止「不是 X，而是 Y」对比句

模型的默认起手式，信息密度低，删掉对比后句子更短更硬。

```
改前：按文件头识别 HEIC，而不是按扩展名。
改后：按文件头识别 HEIC，不按扩展名。
```

「而不是」的变体（「不是…，而是…」）同属此类。

### 2. 禁止排比

三条并列以上、结构对称的句子基本是生成痕迹。留事实，删节奏。

```
改前：更快、更稳、更安全。
改后：（删掉，或写成具体数字：挂载段数上限 20 段，内存不再随对话长度上涨。）
```

### 3. 禁止过渡套话

「值得注意的是」「总的来说」「综上所述」「总而言之」「换句话说」。这些词删掉后句子照常成立。

### 4. 少用强调词

「真的」「非常」「极大地」「显著地」。要强调就给数字或证据，不给副词。

### 5. 禁止结论式收尾

段末硬升华是典型的 AI 腔，例如「这让我们的系统更加健壮」「为用户带来更流畅的体验」。写完事实就停笔。

### 6. 避免欧化长句

一句超过 40 字不接受。复合句拆成并列句，定语从句拆成两句。参考阮一峰规范「句子」一节的长度上限。

### 7. 不使用破折号

改用逗号、句号或冒号。破折号在中文技术写作里只用于解释，而 PR 和文档里它几乎都是口头语停顿。

```
改前：再中止——否则中止引发的异常会走笼统错误回调。
改后：再中止。否则中止引发的异常会走笼统错误回调。

改前：两处"体检基线"修复——`internal/config/settings.go` 的……
改后：两处"体检基线"修复：`internal/config/settings.go` 的……
```

## 排版

- 标点用全角；直引号 `"` 换成「」或“”。
- 中文与英文、数字之间留空格：`跑 test:product-loop`，不写 `跑test:product-loop`。
- 命令、路径、标识符、数值用行内代码格式。
- 顿号用于中文并列词，最后一个用「和」连接。

## 验证

写完长文（PR 正文、新文档）后跑一次句式自检：

```
grep -nE '不是[^。，]{1,20}，而是|而不是|——|—|值得注意的是|综上|总的来说|极大地|这让' 文件.md
```

任何命中都改写该处再提交。这条 grep 只兜底句式，排版（直引号、空格）靠自查，不进 CI。本篇和 `AGENTS.md` 因为引用反例，自身不适用这条 grep。

## 来源对照

这些规矩分三类，别把整个清单都记在那三家名下。

- 直接出自三家规范：全角标点与引号、顿号、中英文空格，以及长句上限、简单句、主动语态（阮一峰《中文技术文档的写作规范》、《中文文案排版指北》）。
- 精神上呼应：过渡套话、强调词、结论式收尾，对应 Microsoft 风格指南的简洁与平静语气原则，但原文没有逐字条文。
- 本仓库自定：「不是 X，而是 Y」对比句、排比禁令，以及破折号禁令。破折号与阮一峰规范有分歧：他允许破折号用于进一步解释，我们禁用，因为仓库里的破折号几乎全是口头停顿，禁用后才能用 grep 机检。真遇到解释性用法，改成冒号即可。
