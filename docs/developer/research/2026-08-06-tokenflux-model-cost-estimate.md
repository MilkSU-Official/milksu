# TokenFlux Grok / DeepSeek 月度成本估算

> 文档状态：**Research / Pricing snapshot**
>
> 核价日期：2026-08-06
>
> 边界：本页是按历史高峰用量和当前公开价格做的预算估算，不是 TokenFlux 的固定报价，
> 也不是 MilkSU 的发布成本承诺。模型价格、路由可用性、缓存规则、套餐额度和汇率变化后
> 必须重新核价。

## 结论

如果 MilkSU 保持当前观察到的高缓存复用，并把主力模型从 GPT-5.6 Sol 切换到 DeepSeek
或 Grok 低价路由，模型成本不是小幅下降，而是可能下降一个数量级。

以历史两个月约 175 亿 Token 的用量折算，单月统计口径为 **87.5 亿 Token**。按当前
TokenFlux 价格和 MilkSU/Pi 实际观察到的 Token 结构估算：

| 模型或路由 | 单月推理积分（鱼板） | 单月直接充值人民币 | 相比 GPT-5.6 Sol |
| --- | ---: | ---: | ---: |
| Grok 4.3 低价路由 | 约 1,727 | 约 ¥173 | 便宜约 27–35 倍 |
| DeepSeek V4 Flash | 约 3,803 | 约 ¥380 | 便宜约 12–16 倍 |
| Grok 4.5 低价路由 | 约 4,103 | 约 ¥410 | 便宜约 11–15 倍 |
| Grok 4.5 SuperGrok | 约 16,925 | 约 ¥1,692 | 便宜约 3 倍 |
| GPT-5.6 Sol，53% Fast | 约 46,735–60,540 | 约 ¥4,674–¥6,054 | 基准 |

因此，在缓存结构不明显恶化的前提下，单月 87.5 亿 Token 使用 DeepSeek 或 Grok 低价
路由，直接充值成本可能只有 **约 ¥170–¥410**；使用 SuperGrok 约为 **¥1,700**，而
继续使用 GPT-5.6 Sol 约为 **¥4,700–¥6,100**。

## 估算口径

本页使用以下假设：

- 月用量：8,750,000,000 Token，即 8,750 个百万 Token 计费单位；
- 新输入：约 2.52%；
- 输出：约 0.88%；
- 缓存读取：约 96.60%；
- GPT-5.6 Sol 的 Fast 使用占比按历史截图中的 53% 计算；
- TokenFlux 直接充值按 1 元人民币兑换 10 推理积分计算；
- 不计固定充值手续费、订阅折扣、日限额、月限额和路由失败重试；
- 这里假设不同模型继续复用相同的上下文、Compaction 和缓存策略。

单个模型的估算公式为：

```text
月推理积分
= 8,750 ×（2.52% × 输入价 + 0.88% × 输出价 + 96.60% × 缓存读取价）

直接充值人民币
= 月推理积分 ÷ 10
```

截图里的累计 Token 只能给出总量，不能还原 Provider 账单里的输入、输出、缓存写入和缓存
读取明细。因此，本页使用 MilkSU/Pi 已观察到的结构作为预算代理，而不是声称已经得到
TokenFlux 的真实账单。

## 核价快照

以下均为每百万 Token 的推理积分价格，来源为
[TokenFlux 模型广场](https://tokenflux.dev/models)：

| 模型或路由 | 输入 | 输出 | 缓存读取 |
| --- | ---: | ---: | ---: |
| Grok 4.3 低价路由 | 1.00 | 2.00 | 0.16 |
| Grok 4.5 低价路由 | 1.60 | 4.80 | 0.40 |
| DeepSeek V4 Flash | 7.00 | 14.00 | 0.14 |
| Grok 4.5 SuperGrok | 6.60 | 19.80 | 1.65 |

GPT-5.6 Sol 按上下文长度和 Fast 模式分档：

| 上下文与模式 | 输入 | 输出 | 缓存读取 |
| --- | ---: | ---: | ---: |
| 0–272K，普通 | 20.00 | 120.00 | 2.00 |
| 272K 以上，普通 | 40.00 | 180.00 | 2.00 |
| 0–272K，Fast | 40.00 | 240.00 | 4.00 |
| 272K 以上，Fast | 80.00 | 360.00 | 4.00 |

DeepSeek 的输入单价明显高于 Grok 4.5 低价路由，但缓存读取只有 0.14 推理积分。对当前
缓存读取占绝对多数的 Harness，DeepSeek 的最终月成本因此可能略低于 Grok 4.5。

## 缓存失效时的敏感性

低价结果高度依赖缓存。为了观察风险，假设同样的 87.5 亿 Token 完全没有缓存，并粗略按
90% 输入、10% 输出分布计算：

| 模型或路由 | 无缓存时单月人民币 |
| --- | ---: |
| Grok 4.3 低价路由 | 约 ¥963 |
| Grok 4.5 低价路由 | 约 ¥1,680 |
| DeepSeek V4 Flash | 约 ¥6,738 |
| Grok 4.5 SuperGrok | 约 ¥6,930 |

这不是常态预测，而是说明缓存命中对成本排序有决定性影响。切换 Provider、频繁切换模型、
改变 System Prompt、破坏缓存键稳定性或让上下文无法复用，都会使真实成本显著高于高缓存
估算。

## MilkSU 的模型路由建议

- 日常编码和长时间自主运行优先使用 DeepSeek V4 Flash；
- 需要原生视觉、截图理解或更强综合能力时使用 Grok 4.5；
- 最困难的架构判断、调试和最终验收阶段临时切换 GPT-5.6 Sol；
- Grok 4.3 可作为极低成本批处理候选，但必须持续观察可用性、输出质量和重试放大；
- DeepSeek 仍是纯文本主模型；图片应继续通过本地 OCR、结构化 UI 观察或明确配置的辅助
  视觉模型转成可审计的文字证据，不能把它描述成获得了原生视觉能力。

如果约 90% 的日常工作由 DeepSeek 或 Grok 承担，只在约 10% 的高难度阶段使用
GPT-5.6 Sol，则当前粗略预算为 **每月约 ¥500–¥1,250**。该混合路由能保留关键阶段的
最高模型能力，同时避免让高价模型承担大量可缓存、可批处理的日常 Token。
