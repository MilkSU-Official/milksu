# ADR-0011：NSSCTF 本地题库、能力画像与可解释推荐

> 文档状态：**Historical ADR**。目录和推荐的原始决策保留；当前 Memory 归属与校准缺口见
> [当前开发目标](/developer/current-objectives)、代码、测试和 Git 历史。
>
> 状态：Accepted for CTF-first M3 MVP（2026-07-31）

## 背景

此前 NSSCTF 公开题库入口只接受一个题号或详情链接。它可以验证单题 Intake 和平台 Judge，但无法回答用户每天打开训练场时真正关心的问题：

- 我现在擅长什么、薄弱什么？
- 下一题应该做哪道，为什么？
- 平台题库更新后，本地训练计划怎样跟着变化？

NSSCTF 当前公开题库页面通过分页列表接口提供约 4204 道题的标题、方向、标签、难度、积分、解出/错误统计和 WP 信号。完整同步不需要逐个抓取详情页。

## 决策

### 1. 显式、限速地同步公开目录

用户选择官方 `https://www.nssctf.cn/problem` 题库后，MilkSU 按 NSSCTF 的十个公开方向分页读取列表。首次全量当前约 211 个小分页，请求间隔固定限速；平台返回 HTTP 或业务码 `429` 时按 2/5/10 秒退避重试。同步只由用户触发，不在每次启动时后台抓取。

同步结果写入应用私有目录的 `nssctf/catalog.sqlite3`。所有分页先在内存中形成候选快照，只有完整读取成功后才在一个 SQLite Transaction 中更新目录、同步时间并清理已下架条目；限流耗尽、中断或解析失败不会暴露半次同步，也不会删除上一次可用快照。

目录同步只保存公开元数据，不读取 Cookie、密码、浏览历史、平台私有进度或附件内容。用户选择具体题目后，现有单题 Adapter 再读取公开详情。

训练场的“公开题库”直接查询这份 SQLite 快照：按题号、题名或标签搜索，按方向筛选，并在后端以 10/20/40 题分页。手工输入题号不再是默认入口；它只是统一搜索框支持的一个查询方式。当前页题目同时与 MilkSU Runtime 的真实 NSSCTF 训练轨迹合并，直接标记未开始、再挑战或已完成；CTFshow 和本地样例不会污染 NSSCTF 题号状态。

### 2. 单用户本机画像，不提前造账号系统

MVP 没有用户表。能力画像属于当前设备上的单一 `local_profile`，直接从 MilkSU Runtime 已记录的 CTF Job 计算，不复制一套可修改的“能力真相表”。

首版雷达采用六个维度：

- Web
- Pwn
- Reverse
- Crypto
- Forensics
- Misc

Mobile 归入 Reverse；取证相关 Misc 题由标签细分为 Forensics；AI、IoT、Ethereum 和实战题首版归入 Misc，等真实训练量足够后再决定是否升格为独立维度。

分数综合尝试次数、成功率、已解题难度、提示依赖和用户独立步骤。没有轨迹的维度保留内部冷启动先验，但 UI 显示“待校准”而不是伪造低分；综合分只聚合真正练过的方向，并单独展示画像置信度。

画像不是 NSSCTF 专属统计。所有经过 Platform Adapter 和真实 Judge 证据进入 Runtime 的训练都按方向计入同一个本机画像；`nssctf-web` 与 `nssctf-agent-arena` 合并为 NSSCTF 来源，`ctfshow-web` 单列为 CTFshow 来源，本地样例不计入。面板同时公开每个平台的尝试数和完成数，让用户能分清能力分来自哪里。平台题号进度仍保持隔离：CTFshow 训练可以提升对应能力维度，但不能把同号 NSSCTF 题标成已尝试。

### 3. 规则推荐先于黑盒模型推荐

首版推荐器是确定性、可测试和可解释的。训练信号先区分 `进行中 / 已通过 / 未通过 / 已取消`：进行中和已通过题不会重复推荐；未通过且已经形成终态的题可以作为复盘候选；未知旧状态和已取消题默认不主动打扰用户。新题按以下信号排序：

- 题目难度是否接近该维度当前建议区间；
- 是否补足薄弱维度；
- 公开解出人数和成功比例是否适合建立快速反馈；
- 同一维度是否已经占据过多推荐位。

每条推荐展示 `校准 / 补短板 / 巩固 / 进阶 / 复盘`、能力证据、题目难度、建议区间和公开解出人数。复盘理由明确展示上一次使用的提示数和独立步骤；为了避免训练流陷入旧失败，六条推荐中最多保留一条复盘题，并固定放在两条新题之后。零置信度方向只能解释为“建立第一条校准记录”，不能声称用户能力是某个确定分数。以后可以让模型帮助解释或生成训练计划，但模型不能直接改写能力分和推荐事实。

当前候选目录仍是 NSSCTF 本地快照，因此界面明确写作“推荐下一道 NSSCTF 题”。题号生命周期只匹配 NSSCTF 任务；跨平台训练用于估计方向能力，不会因为不同平台恰好使用相同数字 ID 而错误排除候选。

### 4. 没有官方赛事字段时，只做可解释的题目系列

公开列表响应当前没有稳定的赛事 ID 或赛事名称字段。MilkSU 不把相邻题号或模型猜测伪装成官方赛事目录，只对 `[赛事名]题目名` / `【赛事名】题目名` 形式的标题前缀做保守归组：

- 同一前缀至少出现 3 题才展示；
- 系列卡展示题数、平均难度、方向以及本机尝试/完成进度；
- 每组保留完整题目目录，并在界面中分页展示；推荐卡片可以保持精简，但不能把未展示的题误写成不存在；
- Runtime 信号为每题标记未开始、再挑战或已完成，并确定第一道尚未完成的下一题；
- 进入系列后先展示进度和“一键开始/继续”，再展开逐题列表，避免用户重新自行规划；
- 产品文档明确记录该归组不是 NSSCTF 官方赛事目录；用户界面只把它称为“系列”，不在主流程堆放实现解释。

如果 NSSCTF 后续提供稳定赛事元数据，再迁移为官方赛事 Adapter；题名前缀只保留作兼容回退。

## 产品流程

1. 用户打开 CTF 训练，直接看到与平台题库相同心智模型的 Challenge Desk；没有本地目录时才显示唯一的同步动作；
2. 首次点击“同步 NSSCTF 题库”，公开目录进入本地 SQLite；
3. 用户在完整分页列表中按题号、题名、标签或题型定位题目，并在右侧直接查看题面与训练状态；
4. 能力画像、继续未完成题和可解释推荐保持为紧凑辅助信息，不替代用户自由选题；题名前缀系列只作兼容回退；
5. 点击推荐或题单项目后复用现有单题详情 Adapter 和 Challenge Workspace；
6. 训练的 Outcome、提示和独立步骤回到 Runtime；再次打开任一已支持题库时，跨平台画像、来源计数、系列完成数与 NSSCTF 推荐随真实轨迹变化。

进入 PI 后，聊天页明确标记“CTF 解题会话”，并提供返回训练工作台的入口。PI 负责分析和写入候选，平台提交、轨迹、Artifact 与复盘仍归训练工作台，避免普通对话取代 CTF Harness。

## 未完成边界

- 当前画像只包含 MilkSU 内由平台 Judge 留下证据的训练记录，没有导入 NSSCTF 或 CTFshow 账号历史；
- 同步没有后台定时器、差量更新时间游标或跨设备账户；
- 当前赛事系列来自保守的题名前缀，不是官方赛事元数据；没有前缀的题不会被强行归组；
- 推荐尚未使用时间衰减、知识点先修图和多臂老虎机探索；
- 最终价值仍要通过真实 NSSCTF 解题、完成率、提示依赖和用户主观反馈验证。
