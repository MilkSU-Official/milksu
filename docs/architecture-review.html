MilkSU 架构设计与竞品分析

Pi Agent Harness 扩展 -- 设计拆解、横向对比、未来方向

1. 项目概述

MilkSU 是一个面向安全领域的 AI Agent 平台。它构建在 Pi（earendil-works 的开源 agent 运行时）之上，用 Tauri v2 包了一层原生桌面客户端。MilkSU 不重新发明 agent 循环 -- 它复用 Pi 已有的 LLM 交互、工具执行、扩展管理能力，在上面叠加安全领域特化的 UI 和技能系统。

什么是 Agent Harness（代理线束）？
"Harness" 这个词借鉴自测试框架。测试线束（test harness）提供结构（setup、teardown、assertion），测试逻辑提供智能。类似地，MilkSU 提供结构（任务面板、权限策略、技能路由），AI agent 提供智能。线束约束和引导 agent，让它在特定领域内更高效。这是理解 MilkSU 设计哲学的核心概念。

技术栈一览

前端React + TypeScript + Vite + Tailwind CSS v4 + shadcn/ui（base-nova 风格）
桌面外壳Tauri v2（Rust 后端，WebView 前端）
Agent 运行时Pi（Node.js），通过 bridge.js 子进程接入
进程间通信stdin/stdout JSON lines（bridge 层）+ Tauri invoke/emit（前后端）
字体 / 主题Geist 字体，oklch 色彩系统，浅色主题
默认 LLMDeepSeek（同时支持 Anthropic、OpenAI、Google Gemini、Groq）
许可证MIT

为什么要三层？
这跟 VSCode + LSP 的分离方式一模一样。Rust 处理窗口管理、安全沙箱、进程生命周期（必须快、必须安全的事）。Node.js 处理 LLM 交互和工具执行（需要丰富生态的事）。两者通过简单协议（stdio JSON lines）通信，零依赖、跨平台。好处是你可以换掉 agent 运行时而不碰桌面外壳，反之亦然。

3. Tauri IPC 双通道

Tauri v2 在前端（WebView）和后端（Rust）之间提供两种通信机制。MilkSU 两种都用，各有各的用途：

invoke -- 请求-响应

前端调用 Rust 函数并等待结果。类似 HTTP POST -- 一个请求，一个响应。用于用户主动操作：

// 前端（TypeScript）
await invokeCommand('send_message', {
  conversationId: id,
  prompt: text
})
// 后端（Rust）
#[tauri::command]
fn send_message(
  conversation_id: String,
  prompt: String
) -> Result<(), String>

emit/listen -- 事件推送

后端随时向前端推送事件。类似 WebSocket -- 由后端决定何时发送。用于 agent 的流式输出：

// 后端（Rust）
app_handle.emit(
  "agent-message",
  AgentMessage { ... }
)?;

// 前端（TypeScript）
listenEvent('agent-message',
  (event) => {
    // 累积文本增量
  }
)
面试 / 演讲要点
这种双通道模式完美映射到 agent 工作负载。用户发送提示词（invoke -- 同步、一次性）。Agent 产生多个输出（emit -- 异步、多次事件）：文本增量、工具调用、状态更新。同样的模式出现在所有 agent 平台中：Codex 用 HTTP + SSE，Claude Code 用 stdio + 事件流。底层原则是：用户意图是请求-响应的，但 agent 行为是事件驱动的。

4. Agent Bridge 模式

bridge.js 是 Tauri 桌面应用和 Pi agent 运行时之间的关键边界。它作为独立的 Node.js 子进程运行，在用户发送第一条消息时由 Rust 启动：

用户输入提示词 → React invoke("send_message") → Rust 启动 bridge.js → Pi createAgentSession() → LLM API 调用
LLM 流式返回 → Pi 会话事件 → bridge.js stdout (JSON lines) → Rust 读取，emit 事件 → React 渲染

为什么不把 Node.js 嵌入 Rust？

在 Rust 进程中嵌入 Node.js 运行时（通过 napi 或 deno_core）会带来巨大复杂性和紧耦合。子进程方案有几个明显优势：

  • 崩溃隔离 -- agent 崩溃时，桌面应用照常运行。用户看到错误消息，而不是窗口卡死。
  • 资源控制 -- 可以干净地 kill 子进程（及其所有子进程）。Agent 中的内存泄漏不影响 UI。
  • 协议简洁 -- stdio JSON lines 跟 LSP（Language Server Protocol）、DAP（Debug Adapter Protocol）用的协议一样。久经考验。
  • 运行时可替换 -- 可以把 Pi 替换成任何能读 stdin、写 JSON 到 stdout 的 agent 框架。
面试 / 演讲要点
这跟 VSCode 的做法一模一样：编辑器（Electron）通过 stdio 启动语言服务器（独立进程）。LSP 用 JSON-RPC；MilkSU 用纯 JSON lines（更简单，因为是单向流式传输不需要请求 ID）。核心洞察是：宿主进程负责 UI 和生命周期，agent 进程负责智能。在进程边界实现关注点分离。

5. Pi 扩展系统

MilkSU 构建在 Pi 之上，而不是 fork 或重新实现。Pi 提供 agent 循环、LLM 集成、工具执行和扩展钩子。MilkSU 把自己注册为 Pi 的扩展，通过扩展 API 添加安全领域特化行为：

Pi APIMilkSU 的用法它做什么
pi.registerTool() 注册安全工具（nmap_scan、browser_connect 等） 工具变得对 agent 可用。TypeBox schema 提供类型安全的参数验证。
pi.on("resources_discover") 返回每个 skill 目录的 SKILL.md 路径 Pi 加载 SKILL.md 文件，用于渐进式披露 -- agent 在上下文中看到技能描述，决定使用哪些工具。
pi.on("before_agent_start") 注入技能路由提示词 skill-router 构建一段系统提示词，列出可用技能和关键词。Agent 据此选择合适的工具。
pi.on("tool_call") 策略引擎拦截（当前是 stub） 可以返回 {block: true, reason} 阻止工具调用。目前是空实现，计划做安全权限分级。

Skill 架构

每个 skill 是一个有标准结构的目录：

skills/network-recon/
  SKILL.md        # YAML frontmatter: name, description, triggerKeywords
  tools/
    nmap-scan.ts  # defineTool() + TypeBox 参数 schema
    report.ts
  prompts/        # 可选的工作流提示词

SKILL.md 文件有双重用途：既是文档（给人看），也是配置（给 skill-loader 解析）。YAML frontmatter 定义元数据；markdown 正文提供上下文，agent 可以读取它来理解 skill 的能力和使用模式。

面试 / 演讲要点
这跟 Claude Code 的 .claude/skills/ 和 Codex 的 Skills 是同一个模式。共同原则：技能是声明式描述，agent 在运行时读取，而不是在 agent 启动前执行的命令式代码。Agent 根据用户意图决定激活哪些技能，不是开发者预先指定。这叫 "渐进式披露"（progressive disclosure）-- agent 只在判定技能相关时才看到详细的工具文档。

6. Task Type 系统

这是 MilkSU 最独特的功能，也是安全领域差异化的核心。每个对话在创建时绑定一个任务类型，它决定了：

  1. 右侧显示什么 UI 面板
  2. 追踪什么结构化状态
  3. 输入框显示什么占位符文本
  4. 侧边栏显示什么图标
类型颜色图标面板内容状态结构
ChatneutralMessageSquare 无（OutputPanel 显示工具结果） 仅消息
Pentest红色Shield 目标卡片、6 阶段追踪器、漏洞列表、开放端口、已用工具 PentestState { target, phase, vulnerabilities[], ports[], tools_used[] }
CTF紫色Flag 挑战卡片（名称、类别、分值）、进度追踪、flag 列表、已解决徽章 CtfState { challenge, category, points, flags[], hints[], solved }
Recon蓝色Network 范围列表、阶段追踪器、主机表、服务表、发现列表 ReconState { scope[], hosts[], ports[], findings[] }
Reverse琥珀色Binary 二进制卡片（名称、架构）、保护机制网格（NX/Canary/PIE/RELRO）、函数表、发现列表 ReverseState { binary, arch, protections{}, functions[], findings[] }

实现细节

  • 面板叠加：TaskPanel 使用 position: absolute 浮动在聊天区域上方，而不是 flex 布局。这防止窗口缩小时聊天区域被挤压到无法使用的宽度。
  • 持久化：task_type 和 task_state 序列化到每个对话的 JSON 文件中，状态在应用重启后保留。
  • 自动显示：创建或选择安全类型对话时，自动打开任务面板。
  • 阶段追踪器：竖向列表，三种图标状态 -- CheckCircle2（已完成）、ChevronRight（进行中，带脉冲动画）、Circle（待处理）。
面试 / 演讲要点
这是 Agent Harness 概念的实际应用。"线束"（任务面板）提供结构 -- 阶段追踪、状态模式、领域特定字段。"Agent"（聊天）提供智能 -- 决定扫描什么、解释结果、选择下一步。两者单独都不够用：agent 没有结构就会产出杂乱无章的发现；结构没有 agent 就是空表格。组合起来才是领域特化的 agent 平台，而不是通用聊天机器人。

7. 流式架构

逐字符实时输出对 agent 用户体验至关重要。MilkSU 通过多跳事件管道实现：

跳数源目标协议事件类型
1LLM APIPi 运行时 SSE / WebSocket（取决于提供商） Token 增量
2Pi 运行时bridge.js Pi 会话事件回调 text_delta、thinking_delta、toolcall_start/end、done、error
3bridge.jsRust (lib.rs) stdout JSON lines 每个 Pi 事件变成一行 JSON，包含 type、id 和事件特定字段
4RustReact (ChatView) Tauri emit("agent-message") AgentEvent { conversation_id, role, content, tool_name, done }

在前端，ChatView 通过累积 assistant_delta 事件来处理流式输出：

if (role === 'assistant_delta') {
  // 找到正在运行的 assistant 消息
  const last = msgs[msgs.length - 1]
  if (last?.role === 'assistant' && last.status === 'running') {
    // 追加到已有消息（逐字符）
    msgs[last] = { ...last, content: last.content + content }
  } else {
    // 开始新的流式消息
    msgs.push({ role: 'assistant', content, status: 'running' })
  }
}

8. 工具结果双通道

当 agent 调用一个工具（比如 nmap_scan），工具返回两个独立的负载：

content -- 给 Agent 看

自然语言文本，LLM 读取后用来做下一步决策。针对推理优化，不是给人看的。

"在 10.0.0.1 上发现 3 个开放端口：
22 (SSH)、80 (HTTP)、443 (HTTPS)"

details -- 给 UI 看

结构化 JSON，前端用来渲染富 UI 元素。不发送给 LLM。

{
  "ports": [
    {"port": 22, "service": "SSH"},
    {"port": 80, "service": "HTTP"},
    {"port": 443, "service": "HTTPS"}
  ]
}

这种分离很重要：LLM 不需要解析 HTML 表格，用户不需要读原始 JSON。每个消费者拿到最适合自己格式的数据。

11. Arkloop 拆解

Arkloop 是一个基于 Go 的 AI agent 平台，采用微服务架构。在这次对比中架构成熟度最高。

架构：7 服务微服务拆分

服务技术栈职责
APIGo认证、RBAC 权限控制、资源管理、审计日志
GatewayGo反向代理、限流、风险评分
WorkerGo任务执行、LLM 路由、工具调度、agent 循环
SandboxGoFirecracker microVM 或 Docker 容器隔离
DesktopElectron + Go原生桌面应用，内嵌 Go sidecar
WebReact / TypeScript用户界面
ConsoleReact / TypeScript管理后台

基础设施：PostgreSQL、Redis、SeaweedFS（对象存储）、OpenViking（向量记忆）。

突出特性

  • Firecracker microVM 沙箱 -- 跟 AWS Lambda 用的是同一技术。每次代码执行跑在一个轻量虚拟机中，亚秒级启动，完全内核级隔离。这是生产级的安全能力，桌面应用做不到。
  • Persona 系统 -- 每个 persona 有独立的系统提示词、工具集、行为配置和 Lua 脚本。就像多个 "角色"，各自有不同能力。MilkSU 的 task-type 系统概念类似但是静态的（5 个固定类型 vs. 任意 persona）。
  • ACP（Agent Communication Protocol） -- agent 间通信协议。Agent 可以互相对话，不只是跟用户对话。支持 "经理" agent 委托 "专家" agent 的多 agent 工作流。
  • 提示词注入防护 -- 语义级扫描，分析用户输入是否包含可能劫持 agent 行为的模式。超越简单的关键词过滤。
  • ClawHub / OpenClaw -- 技能市场，SKILL.md 格式兼容。技能可以跨 Arkloop 实例共享和导入。
Arkloop vs. MilkSU
Arkloop 是一个平台 -- 它有认证、RBAC、管理后台、网关。MilkSU 是一个工具 -- 单用户、无认证、无服务器基础设施。两者在不同尺度上运作。从 Arkloop 学到的不是要复制它的架构，而是 Persona 系统和技能市场是值得学习的模式。

12. Memoh 拆解

Memoh（1,973 stars）采用完全不同的方式：不是在用户机器上运行 agent，而是每个 agent 都有自己的云电脑 -- 一个专用容器，有文件系统、桌面、浏览器和网络。

核心概念：每个 Agent 一台电脑

在 Memoh 中创建一个 bot 时，它得到：

  • 一个专用 Docker 容器，有自己的文件系统
  • 一个虚拟桌面环境（用于 GUI 操作）
  • 一个浏览器实例（用于 Web 自动化）
  • 网络访问（用于 API 调用、下载）
  • 持久化长期记忆（通过 Mem0 或 OpenViking）

Agent 7x24 小时运行，即使用户合上笔记本也不停。这是 "永不休眠的个人助手" 模型。

突出特性

  • 10+ 渠道集成 -- Telegram、Discord、飞书、微信、QQ、邮件。Agent 可以从任何地方被联系到，不只是在 app 内。这让 Memoh 更像 "个人管家" 而不是 "工具"。
  • Agent Hosting（ACP） -- 可以把外部 agent（Codex、Claude Code）托管在 Memoh 工作空间里。聪明的寄生策略：不自己造编码 agent，让你自带，它提供基础设施。
  • Computer Use -- Agent 可以操作容器的虚拟桌面，像人一样点击按钮、填写表单。配合 Browser Use，agent 可以跟任何 Web 或桌面应用交互。
  • 定时任务 -- 周期性心跳和类 cron 调度。Agent 可以每天早上检查邮件、每日爬价格、定时运行安全扫描。
  • 多 bot 架构 -- 多个 bot 可以私聊、群聊或互相对话。跨平台身份绑定意味着同一个 bot 认识你，不管你是从 Telegram 还是 Discord 发消息。
Memoh vs. MilkSU
Memoh 解决的是一个根本不同的问题："我离开后怎么让 agent 继续运行？" MilkSU 解决的是 "怎么让 agent 在安全任务上更有效？" 两者理论上可以互补 -- 想象把 MilkSU 的安全 agent 托管在 Memoh 容器里做 24/7 扫描。从 Memoh 学到的关键点是永不休眠模式：安全扫描（端口扫描、子域名枚举、持续监控）天然适合在后台运行的 agent。

13. Codex & Claude Code

这两个是定义行业标准的商业平台。MilkSU 的路线图部分参照了它们的能力。

Codex (OpenAI)

  • AGENTS.md -- 项目规则文件
  • Skills -- 可复用的任务模板
  • 6 个并发子 agent -- 并行任务执行
  • Permission Profiles -- 按工具类别的 auto/confirm/deny
  • /goal -- 长时间自主任务，关掉会话也继续跑
  • /fork -- 对话分支，并行探索不同方案
  • Automations -- 定时任务（类似 GitHub Actions）
  • 云端沙箱 -- 每个会话在隔离 VM 中运行

锁定 OpenAI 模型。专注编码工作流。

Claude Code (Anthropic)

  • CLAUDE.md -- 项目规则文件
  • .claude/skills/ -- 技能目录
  • 5 层 agent 嵌套 -- agent 启动 agent
  • Workflows -- 确定性 JS 脚本编排多个子 agent
  • Hooks -- PreToolUse、Stop、Notification 生命周期事件
  • Auto Mode -- 基于分类器的权限系统
  • .claude/memory/ -- 跨会话持久记忆
  • Computer Use + Chrome 扩展 -- GUI 自动化
  • Plugin 市场 -- 社区扩展

锁定 Anthropic 模型。最深的 CLI 集成。

该学什么
/fork（Codex）是对安全工作最有价值的概念。渗透测试天生就是分支的：你发现 3 个入口点，每个需要独立探索。对话 fork 让 agent 在不污染各自上下文的情况下追踪所有路径。

Hooks（Claude Code）是真正的策略引擎的基础。PreToolUse 让你在工具运行之前拦截（比如 "你确定要对生产环境跑 sqlmap 吗？"）。Stop 让你中止正在运行的操作。这直接映射到安全审批工作流。

不该抄的：云沙箱（对桌面应用太重）、插件市场（需要规模才有用）、定时自动化（需要服务器）。

14. 差异化总结

平台别人没有的独特能力
MilkSU 任务类型面板 按对话绑定安全领域，带专用状态追踪和阶段推进。没有其他平台做了根据工作类型变化的领域特定 UI。
Pi harness 构建在真正的 agent 运行时之上，不是裹了层 API 调用的聊天壳。扩展系统提供结构化的集成点。
Codex /goal 长时间自主任务，关掉会话也继续运行。Agent 在你离开后继续工作。
/fork 对话分支。并行探索多个方案而不丢失上下文。
Claude Code Workflows 确定性 JS 脚本编排多个子 agent，支持扇出、屏障和结构化输出。脚本化的智能。
完整生命周期钩子 PreToolUse + Stop + Notification。最完整的拦截系统。
Arkloop Firecracker VM 微虚拟机级隔离。生产级沙箱。
Persona + Lua 完全可定制的 agent 行为，无需改代码。
ACP Agent 间通信协议。
Memoh 每个 agent 一台电脑 每个 agent 得到完整容器（文件系统 + 桌面 + 浏览器）。
永不休眠 合上笔记本 agent 也在跑。7x24 小时运行。

15. 战略定位

MilkSU 不应该追 Arkloop / Memoh 的路线。

它们在做通用 AI 平台，有微服务、容器编排、多渠道集成和 SaaS 基础设施。MilkSU 是一个人的项目 -- 拼基础设施广度必输。

正确的打法是垂直特化。 MilkSU 的 task-type 系统已经是独有的差异点，其他四个平台都没有。每个后续功能都应该加深这条护城河：

  • 通用功能（子 agent、hooks、记忆）-- 做到够用即可，目的是解锁安全工作流
  • 安全功能（攻击图、权限分级、扫描报告）-- 重点投入，这是护城河
  • 平台功能（认证、RBAC、多渠道、容器）-- 完全跳过

16. 六个方向

1
工具结果 -> 面板状态

目前任务面板是空壳 -- 有结构但没数据。关键的下一步是闭合循环：当 agent 跑 nmap_scan 时，工具结果自动解析到面板的端口表、漏洞列表和阶段推进中。

实现路径

bridge.js 已经会发出带结构化 details 负载的 tool_call 事件。前端需要按任务类型做状态 reducer：

// 当 nmap_scan 返回结构化结果时：
case 'nmap_scan':
  return {
    ...state,
    ports: [...state.ports, ...result.ports],
    phase: Math.max(state.phase, 1), // 推进到 "Scanning"
    tools_used: [...state.tools_used, 'nmap']
  }

这是影响最大的单个变更 -- 它把 MilkSU 从 "带侧边栏的聊天应用" 变成 "安全操作仪表盘"。

2
安全感知的自动模式

Codex 有 Permission Profiles，Claude Code 有 Auto Mode 分类器。两者都是通用的 -- 按 "读" vs. "写" vs. "危险" 分类工具。MilkSU 可以做它们做不了的事：安全领域特化的权限分级。

三级安全权限模型

级别工具行为理由
被动 whois、dig、nslookup、ping、traceroute 自动允许 仅信息收集，不向目标发包，无法律风险
主动 nmap、gobuster、ffuf、nikto 每个目标确认一次 向目标发包，可能触发 IDS / 告警，需要授权
利用 sqlmap、metasploit、hydra 每次调用都确认 主动利用漏洞，可能造成损害，有法律风险

这直接映射到真实渗透测试方法论：被动侦察总是安全的，主动扫描需要范围确认，漏洞利用需要逐次明确授权。

3
攻击图 / Fork

借鉴自 Codex /fork，但适配安全场景。渗透测试天然是分支过程：你发现多个入口点，需要独立探索每一个。对话 fork 让 agent 在不污染上下文的情况下追踪并行攻击路径。

超越 /fork：攻击图可视化

Codex 的 /fork 是纯文本的 -- 你看到两个对话线程。MilkSU 可以更进一步，把 fork 可视化为嵌入 TaskPanel 的攻击图：

初始侦察
  |-- 端口 22 (SSH)
  |     |-- 暴力破解（失败）
  |     '-- .git 泄露密钥（成功!）
  |-- 端口 80 (HTTP)
  |     |-- SQL 注入（进行中）
  |     '-- 目录遍历（发现 /admin）
  '-- 端口 443 (HTTPS)
        '-- 证书分析（无发现）

每个节点是一个对话 fork。树形图展示哪些路径成功、哪些失败、哪些还在探索中。这是其他平台做不了的，因为它们没有领域特定的面板 UI。

4
后台扫描 / /goal 模式

借鉴自 Codex /goal + Memoh 永不休眠。安全扫描常常是长时间任务：全端口扫描可能几小时，子域名枚举跑一整夜，持续监控永远不停。

桌面友好的实现方式

MilkSU 不需要云容器（Memoh）或云 VM（Codex）。Tauri 可以让 bridge.js 作为后台进程继续运行：

  • 用户启动扫描，关闭窗口（但不退出应用 -- Tauri 留在系统托盘）
  • bridge.js 继续运行 agent 循环
  • 扫描完成时，macOS 通知："渗透测试完成：发现 3 个漏洞"
  • 用户点击通知，MilkSU 窗口打开，TaskPanel 已填充数据

比 Memoh 的容器模型简单得多，但覆盖了安全工作流 90% 的场景。

5
Web 渗透的视觉循环

browser-connect skill 已经有 CDP（Chrome DevTools Protocol）骨架。加上视觉模型（DeepSeek-VL、GPT-4o vision）就能实现截图 -> 理解 -> 行动循环，专门用于 Web 渗透测试：

  1. browser_screenshot 截取当前页面
  2. VL 模型分析："这是一个登录表单，有用户名/密码字段和验证码"
  3. Agent 决策："在用户名字段尝试 SQL 注入，暂时跳过验证码"
  4. browser_type 输入 payload，browser_click 提交
  5. 新截图，循环重复

跟 Claude Code 的 Computer Use 不同，因为它是安全上下文感知的：agent 不只是 "操作电脑" -- 它在专门寻找漏洞、测试绕过、在 TaskPanel 中记录发现。

6
报告导出 + 发现数据库

之前被定为 "为时过早"，但一旦面板状态填充完成（方向 #1），导出就是自然的延伸。TaskPanel 中的结构化数据已经是正确的格式了：

  • Markdown 渗透报告 -- 目标、范围、方法论阶段、带严重级别的发现、建议
  • JSON 发现文件 -- 机器可读，可导入漏洞管理工具（Defect Dojo 等）
  • CSV 端口/服务列表 -- 用于电子表格分析
  • 跨对话聚合 -- 同一个目标扫描过多次？合并发现成完整画面

这完成了端到端工作流：发现（agent）-> 追踪（面板）-> 报告（导出）。

17. 优先级路线

阶段做什么为什么排在这前置依赖

18. 最终总结

定义 MilkSU 战略的三句话

1. 不做平台，做工具。 Arkloop 和 Memoh 是带认证、RBAC、多渠道、容器的平台。MilkSU 是给安全从业者用的专注工具。一个人拼不过团队的基础设施广度；一个人可以在专业度上超过通用产品。

2. Task-type 系统是护城河。 没有其他 AI agent 平台有根据工作类型变化的领域特定 UI。每个功能都应该加深这一点：工具结果填充面板，权限分级匹配安全方法论，攻击图可视化 fork 路径。

3. 偷概念，不偷架构。 从 Codex 偷 /fork（攻击路径分支），从 Memoh 偷永不休眠（后台扫描），从 Claude Code 偷 hooks（安全门禁）。但用轻量桌面功能实现，不用微服务。
